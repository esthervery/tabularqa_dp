65개 도메인별 실제 테이블(비즈니스, 헬스 등 총 300만 행 이상, 컬럼 1,615개)에 걸쳐 
522개 질문(qa)을 풀어 일반화 성능을 재는 것을 목적으로 구축된 에이전트
그래서 프롬프트가 매번 스키마와 타입을 설명하는 층을 갖고 있음(처음 보는 테이블에 대응)


======================================================================================
pipe는 ErrorFixingAndTimeoutPipeline이고, 그 안에 
- main_pipeline(정상 경로)과 
- error_fix_pipeline(실패 시 재시도)이 들어 있음.

pipe(row)를 호출하면 run_one(row)이 돌고,
row는 {"question": "What is the average Credit_Limit?", "dataset": "CardBase"}

정상 경로가 실패하면(__CODE_ERROR__ 또는 __TIMEOUT__으로 시작하는 출력) 
-> 오류 수정 경로를 최대 num_attempts=2회 더 시도하고,
    전체는 max_timeout=600초 제한
    아까 "0th/1th/2th error fixing"이 찍혔던 게 재시도 루프

main_pipeline의 네 단계
Pipeline.run_one이 
    1. 프롬프트 생성 (core/prompt_generators.py)
        - LLM은 CardBase 파일을 직접 열어보지 못하기 때문에,
        - 코드를 쓰게 하려면 "이 테이블에 어떤 컬럼이 있고 값이 어떻게 생겼는지" 알려줘야 함
        - YAML에서 prompt_generator: "num_rows: 5"가 그 설정값인데, 실제 데이터에서 5개 행을 뽑아 프롬프트 문자열에 그대로 써넣는다는 뜻
        - CardBase의 경우 실제 카드번호나 신용한도 값 몇 개가 프롬프트에 문자열로 박혀 OpenAI에 전송됨
        | 우리 실험에서는 위처럼 데이터를 전송하지 말고, 스키마는 알고 있다고 가정하는 거 어떨지...
        - 중첩 구조?
            - YAML을 보면 prompt_generator 항목 안에 또 prompt_generator가 들어 있는 구조
            - 바깥 클래스가 안쪽 클래스를 인자로 받아서 감싸는 형태(래핑)
            - 동작 순서는 안에서 바깥 방향 
            (1) 가장 안쪽 ZeroShotDetailedTypesRowsExValuesNullsOneLineRowsVol2
                → 반환값은 문자열 하나(res)이고 네 개의 부분으로 이루어짐
                    1) # TODO: ...: {question}      -> question 부분
                    2) def answer(df: pd.DataFrame) -> 함수 서명, 실행 단계에서 df를 넣고 호출할 함수 이름이 고정됨
                    3) custom_info_csv_2(df)        -> 컬럼별로 컬럼명, non-null 개수 등 테이블 정보 CSV를 만듦, 실제 데이터 N행(예시)
                    4) df.columns                   -> 컬럼 종류
            (2) FewShotChainOfThoughtBuilderWithTypesRowsAndPredictingResultingTypesVol2가
                → annotation/annotations_cot.json에서 읽은 예시 9개(사람이 쓴 chain-of-thought 주석 포함)를 그 앞에 붙여서 긴 프롬프트를 완성
                → few-shot 프롬프트를 만들고, 여기서 답의 타입까지 미리 예측하게 유도
            (3) 마지막으로 ClaudeMessageEmbeddingPromptGenerator가
                → Bedrock Anthropic용 dict({'messages': [...]})로 포장
                → 미완성 코드를 assistant 턴에 넣어 이어쓰게 하는 prefill 방식
                → 이 맨 바깥 포장을 OpenAIAnswerer._flatten이 다시 평문으로 되돌려 쓰는 셈
    2. 모델 호출 
        - 모델 호출은 이제 OpenAIAnswerer가 담당 
            → 텍스트, 입력토큰, 출력토큰을 돌려줌.
    3. 후처리 
        - 후처리기 TillReturnLinePostProcessorMultipleIndents가 응답을 줄 단위로 훑어
            → return으로 시작하는 줄까지만 남기고 들여쓰기를 4칸 기준으로 재구성
            → "expected an indented block" 오류가 났던 게 이 단계의 산출물이 함수 본문 형태가 아니었기 때문
    4. 실행을 순서대로 함
        - 실행기(원래 SaferMultiLineStatementExecutor, 지금은 스레드판)가 후처리된 코드를 def answer(df): 밑에 붙여 exec하고,
        - 네임스페이스에 df, pd, np, ast만 넣은 뒤
        - ans = answer(df)의 결과를 반환
            → 여기서 df는 generic_load_table("CardBase"), 즉 competition/CardBase/all.parquet

결과적으로 실험에서
    - 에이전트의 "응답"은 생성된 pandas 코드를 실제 500행에 실행한 값이고,
        → 지금은 그게 참평균과 정확히 같음(현재 조건에서 이 파이프라인은 결정론적 계산기)
    - 변동성이 생길 여지는 코드 생성 단계(temperature, 프롬프트 표현)와 오류 수정 경로가 개입할 때
    - 실제 코드를 눈으로 보려면 
        → pipe.main_pipeline.run_one(row)이 (prompt, raw_output, postprocessed, output, in_tok, out_tok) 6개를 돌려주니 
        → postprocessed를 출력하면 됨.


======================================================================================
루트에 main.py(CLI 진입점, argparse로 config·결과경로를 받아 SerialLooper를 돌림)
config/에 파이프라인 명세 YAML 다섯 개
    - main.py의 instantiate_pipeline_from_yaml이 그 문자열을 읽어 실제 파이썬 객체를 만듦
    - "다양한 에이전트"를 만들 핵심 지점
    - YAML이 class_name과 arguments로 프롬프트 제너레이터·answerer·후처리기·실행기를 조립하는 선언형 구조
    - 파일을 복사해 answerer의 class_name이나 temperature, few-shot 예시 수, num_rows(테이블 미리보기 행 수)만 바꿔도 다른 에이전트가 됨
core/가 구현부
    - prompt_generators.py에 제너레이터 계층
        → 파일 상단에 상속 트리가 주석으로 정리
    - model_calls.py에 answerer들   
        → Bedrock 2종, Ollama 6종 — 각 모델마다 generate판과 chat판
        → 여기에 우리가 OpenAIAnswerer를 추가한 셈
    - pipelines.py에 에 Pipeline과 ErrorFixingAndTimeoutPipeline
    - executors.py에 실행기
    - postprocessors.py에 후처리기
    - loops.py와 saver.py에 배치 순회·결과 저장
    - eval.py에 DataBench 채점
    - cost.py에 토큰 단가 누적
    - utils.py에 테이블 로더와 annotation_reader
    - santypes.py에 타입 별칭이 들어 있음
나머지 둘은 부속
    - annotation/annotations_cot.json이 few-shot 예시 9개의 사람이 쓴 chain-of-thought 주석
    - assets/Architecture.png는 논문 그림
